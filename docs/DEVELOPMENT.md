# Разработка

Заметки для тех, кто меняет код или выпускает релиз. Пользователю приложения
это читать не нужно — ему достаточно [README](../README.md).

## Устройство

```
Sources/MacOSUtilities/    приложение на SwiftUI
Sources/…/AutoSwitch/      автопереключение раскладки: перехват, словарь, замена
Resources/Scripts/         bash-скрипты, которые приложение выполняет и показывает
scripts/build-app.sh       сборка .app, DMG, подпись, нотаризация
scripts/make-icon.swift    иконка рисуется кодом, а не картинкой
```

Приложение общается со скриптами через строки вида `@@КЛЮЧ=значение`: скрипт
печатает их в общий поток, приложение вынимает их из вывода и рисует по ним
карточку диагностики. Всё остальное, что печатает скрипт, попадает
в раскрывающийся журнал выполнения как есть. Один и тот же файл скрипта
и выполняется, и показывается по кнопке «Показать весь скрипт» — расходиться
им негде.

## Проверки

```bash
./Resources/Scripts/airdrop-fix.sh selftest
```

Разбор `etime` из `ps` — единственная нетривиальная логика в скриптах
(четыре формата: `45`, `3:07`, `2:10:30`, `15-21:20:16`), она закрыта
самопроверкой.

Логика автопереключения — своей проверкой в самом приложении:

```bash
"./build/MacOS Utilities.app/Contents/MacOS/MacOSUtilities" --selftest
```

Она закрывает три нетривиальных места: перевод нажатий через системную раскладку,
поправку на то, что английский словарь macOS считает любую кириллицу правильным
словом, и таблицу посимвольного перевода для выделенного текста.

Целиком, на живой клавиатуре, — отдельным стендом. Он печатает настоящими
событиями в TextEdit и читает результат через универсальный доступ:

```bash
# приложение запущено, раздел «Автопереключение» включён, открыт пустой TextEdit
swift scripts/e2e-autoswitch.swift
```

Стенд проверяет четыре сценария: правку на пробеле с переключением раскладки,
неприкосновенность правильного английского слова, ручное сочетание и возврат.

Два служебных режима самого приложения:

```bash
# отрисовать разделы в PNG — этим сделаны скриншоты в README
"./build/MacOS Utilities.app/Contents/MacOS/MacOSUtilities" --snapshot docs/

# напечатать идеальную высоту каждого раздела при заданной ширине колонки
"./build/MacOS Utilities.app/Contents/MacOS/MacOSUtilities" --measure 688
```

По второму подобран размер окна по умолчанию: высота взята по самому высокому
разделу плюс запас на баннер с итогом, чтобы в исходном состоянии не появлялась
вертикальная прокрутка. Меняете вёрстку разделов — перезамерьте и поправьте
`.defaultSize` в `MacOSUtilitiesApp.swift`.

## Подпись и нотаризация

Без переменных окружения скрипт ставит ad-hoc подпись: работает на своей машине,
но у скачавшего Gatekeeper выдаст предупреждение. Для раздачи нужны две вещи
из платной подписки Apple Developer Program.

**Сертификат Developer ID Application.** Не «Apple Development» и не «Apple
Distribution» — те для отладки и для App Store. Выпустить его может только
Account Holder, роли Admin этот тип недоступен.

1. Keychain Access → «Ассистент сертификации» → «Запросить сертификат у бюро
   сертификации» → сохранить CSR на диск.
2. [developer.apple.com/account/resources/certificates](https://developer.apple.com/account/resources/certificates)
   → «+» → **Developer ID Application** → Profile Type **G2 Sub-CA** →
   загрузить CSR → Download.
3. Двойной клик по `.cer`.

```bash
security find-identity -v -p codesigning | grep "Developer ID"
```

Приватный ключ существует в единственном экземпляре, и Apple его не
восстанавливает: сразу выгрузите сертификат из Keychain Access в `.p12`
с паролем и положите в надёжное место. Число сертификатов Developer ID
на аккаунт ограничено — лишние не выпускайте.

**Профиль notarytool.** Нотаризация — отправка сборки в Apple на автоматическую
проверку; без неё Gatekeeper на чужой машине ругнётся даже на подписанное
приложение. Нужен пароль приложения с [appleid.apple.com](https://appleid.apple.com)
→ «Вход и безопасность» → «Пароли приложений»:

```bash
xcrun notarytool store-credentials notary \
  --apple-id "почта@apple.id" \
  --team-id TEAMID \
  --password "xxxx-xxxx-xxxx-xxxx"
```

Team ID виден в скобках в имени сертификата и на странице Membership.

**Сборка:**

```bash
SIGN_ID="Developer ID Application: ВАШЕ ИМЯ (TEAMID)" \
NOTARY_PROFILE=notary \
./scripts/build-app.sh --dmg
```

Скрипт подпишет приложение с hardened runtime и меткой времени, отправит его
на нотаризацию, прикрепит штамп к самому бандлу, затем соберёт DMG, подпишет
и нотаризует уже его и прикрепит штамп туда же. Два штампа нужны оба: на DMG —
чтобы образ открылся, на `.app` — чтобы приложение запустилось после переноса
в `/Applications` даже без интернета. Каждая нотаризация занимает несколько
минут.

Проверка готового файла:

```bash
spctl -a -vvv -t install dist/MacOS-Utilities-1.1.0.dmg
```

Ожидаемый ответ — `accepted`, `source=Notarized Developer ID`.

## Ограничения

Приложение не в песочнице: `hidutil`, `launchctl` и `defaults` из App Sandbox
не работают. Поэтому в Mac App Store его выложить нельзя — только прямой
раздачей с подписью Developer ID.

Откат раздела раскладки возвращает системный шорткат и снимает ремап, но не
восстанавливает произвольный прежний `UserKeyMapping`, если он был сложнее
одного правила — HID-ремап снимается целиком.
